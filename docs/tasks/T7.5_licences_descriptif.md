## Chantier A — implémenté

### Décisions de conception (séance du 15/10/2026)
1. **Référentiel élargi** : la liste initiale (7 licences) ne couvrait pas le référentiel complet du filtre du site. Ajout de `odc-by`, `odc-pddl`, `other-attribution`, `other-pd` (11 licences acceptées au total).
2. **Règle sécurisée pour `notspecified`** : acceptée uniquement pour un producteur public (`service_public`, `collectivite_territoriale`, présomption CRPA) ; refusée pour un producteur privé. Une licence **incompatible explicite** (fermée, commerciale) reste refusée quelle que soit l'organisation — jamais contournée, même pour un établissement public. Sur data.gouv.fr il ne devrait pas y en avoir ; le principe est conservé pour l'ouverture future à d'autres sources.
3. **Paramétrage JSON** : la politique vit dans `config/politique_licences.json`, avec une clé par source (`data.gouv.fr`) — préparation de T7.4. En l'absence ou en cas d'invalidité du fichier, une politique intégrée équivalente s'applique (comportement sûr, sans exception).

### Fichiers modifiés

- `src/core/licence.py` (v2) : `charger_politique()` (chargement JSON + fallback intégré), `licence_est_acceptable(licence, type_organisation=None, politique=None)`, mémoïsation, `reinitialiser_politique()` (tests). Comportement inchangé pour les appels existants (signature rétrocompatible).

## Chantier B — implémenté

### Décisions de conception (séance du 15/10/2026, suite)
1. **Type d'organisation via les badges uData** : le payload de recherche (`/api/1/datasets/`) embarque `organization.badges` ; `public-service` → `service_public`, `local-authority` → `collectivite_territoriale` (vérifié sur Etalab et Ville de Paris en production). Aucun appel API supplémentaire. Sans badge type : organisation considérée comme privée (comportement sûr).
2. **Marquage des acceptations conditionnelles (options 2+3 validées par le concepteur)** :

Invariants identiques : aucune entrée supprimée après écriture, persistance entre exécutions, anti-doublon par `id_jeu`.
