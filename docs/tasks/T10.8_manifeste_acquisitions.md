## Contexte et motivation

Constat de la validation T11.3 (séance du 19/10/2026) : en mode agentique (`chat`), rien ne relie simplement un fichier de `data/raw/<id_execution>/` au jeu de données correspondant.

- Le nommage (`stockage.md`) : `data/raw/<id_execution>/<id_ressource>_<nom_original>.<ext>` — le nom original vient de l'URL de la ressource, pas du jeu.
- L'**inventaire persistant T10.2** (`data/executions/<id>/inventaire.json`) : écrit uniquement par les commandes CLI (`list`/`download`/`query`/`extract`) ; en mode `chat`, l'inventaire vit en mémoire et disparaît en fin d'exécution.
- Le journal `conversations/<id>/conversation.jsonl` contient tout, mais il faut le parser et le croiser pour retrouver le lien fichier → jeu.

La partie 2 (via T10.1, normalisation B7) devra consommer pour chaque fichier : le jeu de données source, la licence, la mention d'attribution (exigence T7.5 : la mention suit les données jusqu'à la visualisation), le format, la voie d'acquisition. En l'état, ce lien devrait être reconstruit par croisement de trois sources fragiles.

## Décision de conception (actée 19/10/2026)

Écrire **au cœur** (pas côté CLI), à chaque acquisition réussie de `telecharger_brut` et `extraire_ressource`, une entrée dans :

```
data/raw/<id_execution>/manifeste_acquisitions.json
```

**Propriétés** :
- fonctionne dans les deux modes (manuel et agentique) sans duplication de code ;
- **additive** : aucune évolution de contrat (le manifeste est une sortie latérale), nommage des fichiers et sorties normalisées inchangés ;
- l'inventaire T10.2 et le journal conversation.jsonl restent inchangés — le manifeste devient la **source de vérité acquisition côté disque** ;
- la demande utilisateur (prompt `chat` ou rappel de commande) figure en en-tête : traçabilité complète de l'exécution.

## Format du manifeste

```json
{
  "id_execution": "20261019_175304",
  "demande": "Peux-tu rechercher des jeux de données sur les résultats nationaux des élections présidentielles ?",
  "generé_le": "2026-10-19T18:02:11",
  "acquisitions": [
    {
      "fichier": "c65f9e3a-..._resultats-par-niveau-fe-t1-france-entiere.csv",
      "voie": "extraction",
      "id_ressource": "c65f9e3a-87d1-4a0b-9006-6baa3fe9f419",
      "titre_ressource": "resultats-par-niveau-fe-t1-france-entiere.csv",
      "id_jeu": "62581fdf02e05e365ea227a1",
      "titre_jeu": "Élection présidentielle des 10 et 24 avril 2022 - Résultats définitifs du 1er tour",
      "organisation": "Ministère de l'intérieur",
      "url_jeu": "https://www.data.gouv.fr/fr/datasets/election-presidentielle-des-10-et-24-avril-2022-...",
      "licence": "notspecified",
      "licence_conditionnelle": true,
      "mention_attribution": "Source : Ministère de l'Intérieur — ...",
      "tronque": false,
      "nb_lignes": 1,
      "horodatage": "2026-10-19T17:53:32"
    }
  ]
}
```

Champs `voie` : `telechargement` | `extraction`. Les champs absents de la voie concernée sont omis (ex. `tronque`/`nb_lignes` pour la voie 2).

## Plan d'implémentation

### Prérequis détectés (E0 — à traiter en premier)
- **`src/core/resources.py`** : `_jeu_courant` ne retient ni `titre` ni `url` du jeu — or le payload v2 du détail les contient (`title`, `page`). Enrichissement : `"titre": data.get("title")`, `"url": data.get("page", "")` ; propagation dans `_normaliser_ressource` (`titre_jeu`, `url_jeu`) — rétrocompatible avec l'inventaire T10.2 (la sérialisation additive `decharger_inventaire` embarque les nouveaux champs sans changement de schéma).
- Vérifier `mention_attribution` : déjà retournée par les deux voies (`telecharger_brut`/`extraire_ressource`, T7.5) — disponible au point d'écriture, rien à ajouter.

### E1 — Module manifeste (`src/core/manifeste.py`, création)
- `NOM_MANIFESTE = "manifeste_acquisitions.json"`.
- `enregistrer_acquisition(id_execution, entree)` : lecture du manifeste existant (s'il y en a un), ajout de l'entrée, réécriture atomique (écriture `.part` puis renommage, même convention que `telecharger_fichier`) ; création du répertoire à la volée.
- `consigner_demande(id_execution, demande)` : écrit/réinitialise l'en-tête (`id_execution`, `demande`, `generé_le`) en début d'exécution — appelé depuis `main.py` (commandes `chat`, `download`, `extract`) ; idempotent.
- `lire_manifeste(id_execution)` : lecture + parsing défensif (fichier absent → `None`, JSON invalide → `None` + log warning) — jamais d'exception vers l'appelant.
- Invariants : anti-doublon sur `fichier` (même fichier acquis deux fois dans la même exécution = collision déjà suffixée par `resoudre_collision`, donc noms distincts — pas de conflit attendu, garde quand même) ; échec d'écriture → log warning, **jamais d'échec de l'acquisition** (le manifeste est une commodité, pas une dépendance).

### E2 — Branchement des deux voies
- **`src/core/download.py`** (`telecharger_brut`, après le succès) : `enregistrer_acquisition` avec `voie="telechargement"`, fichier, id_ressource, titre_ressource, id_jeu, titre_jeu, organisation, url_jeu, licence, licence_conditionnelle, mention_attribution (déjà calculée), horodatage.
- **`src/core/extraction.py`** (`extraire_ressource`, après le succès d'écriture du CSV) : idem avec `voie="extraction"`, plus `tronque` et `nb_lignes` (déjà dans le retour).
- Métadonnées sources : inventaire (via la ressource normalisée enrichie E0) — même chemin mémoire que `telecharger_brut` actuel, aucun appel API supplémentaire.

### E3 — `src/main.py` : consigne de la demande
- Commande `chat` : `consigner_demande(id_execution, prompt)` avant la boucle.
- Commandes `download`/`extract` : `consigner_demande(id_execution, "download --id-ressource <id>")` (rappel synthétique de la commande) — même mécanique.
- `search`/`list`/`query` : non concernées (pas d'acquisition).

### E4 — `src/utils/storage.py` : enrichissement de `lister_fichiers`
- `lister_fichiers` : inchangé (compatibilité).
- Nouvelle fonction `lister_acquisitions(id_execution)` : retourne les entrées du manifeste (via `lire_manifeste`), ou liste vide.
- (Optionnel à trancher) : une commande CLI `acquisitions --id-execution <id>` affichant le manifeste lisible — aide au mode manuel, à décider avec le concepteur.

### E5 — Tests
- TU manifeste : écriture/lecture round-trip, réécriture additive (2 acquisitions successives → 2 entrées), écriture atomique (pas de `.part` résiduel), fichier absent/vide → `None` sans exception, anti-doublon.
- TU branchement : `telecharger_brut` succès → entrée dans le manifeste (voie téléchargement, champs exacts) ; échec → **aucune** entrée ; `extraire_ressource` succès → entrée (voie extraction, `tronque`, `nb_lignes`) ; échec HTTP → aucune entrée.
- TU enrichissement E0 : `_jeu_courant` contient titre/url du jeu ; inventaire sérialisé les embarque.
- TU consigne demande : `chat` écrit l'en-tête (mock), idempotence de `consigner_demande`.
- TI : flux complet voie 1 et voie 2 dans une même exécution simulée → un manifeste unique, deux entrées distinctes avec voies différentes.
- Comptes rendus : mise à jour de `tests/plan_tests.md` (section T10.8).

### E6 — Documentation et validation
- `docs/specs/stockage.md` : section manifeste (format, invariants, atomicité).
- `docs/architecture/telecharger_brut.md` + `extraire_ressource.md` : mention du manifeste en sortie latérale.
- `docs/design/decisions_conception.md` : décision (source de vérité acquisition côté disque, additif sans contrat).
- README : paragraphes `data/raw` et traçabilité.
- `SESSIONS.md`, kanban (déplacement), ce fichier de suivi.
- **Validation en réel par le concepteur** : scénario `chat` multi-acquisitions (le cas étalon des 2 tours 2022 doit produire un manifeste à 2 entrées avec titres distincts) + scénario manuel `download`.

## Risques identifiés
- Écriture concurrente : deux acquisitions simultanées dans une même exécution (cas agentique séquentiel — la boucle est synchrone, pas de concurrence réelle ; garde par écriture atomique).
- Manifeste volumineux : nombre d'acquisitions par exécution faible (plafond d'invocations) — négligeable.
- `id_execution` non fourni à `telecharger_brut`/`extraire_ressource` en mode agent : vérifier la valeur par défaut réelle (elle existe déjà pour le nommage des fichiers, même source).
